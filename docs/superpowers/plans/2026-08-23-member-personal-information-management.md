# 조합원 개인정보 수정·이력 관리 구현 계획

## 1. 데이터 기반

- 개인정보 프로필, 변경 요청, 변경 이벤트 모델과 마이그레이션을 추가한다.
- PeopleON 외부 ID 및 수동 반영 상태를 저장한다.

## 2. 도메인과 API

- 허용 필드, 검증, 마스킹, 상태 전이를 순수 유틸로 구현하고 테스트한다.
- 본인 프로필 조회·변경 요청 API를 구현한다.
- 관리자 승인·반려·PeopleON 반영 완료 API를 구현한다.

## 3. 화면

- 기존 `내정보` 시작 위치에 프로필 카드와 변경 이력을 추가한다.
- 수정 요청 대화상자와 상태 피드백을 제공한다.
- 관리자 PeopleON 조합원 관리 페이지에 개인정보 변경 요청 처리 영역을 추가한다.

## 4. 검증

- 권한, 중복 요청, 승인 반영, 반려, 마스킹, 환불 조합원 비노출 테스트를 실행한다.
- 데스크톱·모바일 UI 리뷰를 수행한다.
- `pnpm lint`, `pnpm test`, `pnpm build`를 통과한다.

## 후속: 확인 중심 5개 카드

1. 프로필 API에 가입일과 현재 역할 상태를 추가하고 기존 마스킹·환불 평형 비노출 계약을 유지한다.
2. 개별 항목의 상시 연필 버튼을 제거하고 다섯 카드의 요약 정보로 재구성한다.
3. 원장 정보 정정과 연락처 변경만 카드 단위 행동으로 제공하고 기존 수정 요청 대화상자를 재사용한다.
4. 서류 화면은 실제 문서·요청 상태만 요약하고 `/library` 또는 기존 개인자료 구역으로 연결한다.
5. 보안 화면은 현재 제공되는 세션·비밀번호 기능만 표시하며 기기 관리나 전체 로그아웃을 작동하는 것처럼 표현하지 않는다.
6. 변경 이력을 기본 접힘으로 바꾸고 데스크톱·모바일 가독성과 기존 납부 탐색 동작을 검증한다.

## 후속: PeopleON 원장 값 채우기

1. PeopleON 원장 프로필 조회 모듈을 추가하고 키는 서버 환경변수에서만 읽는다.
2. 저장된 외부 고유 ID로 한 행을 확정한 뒤 개인정보 API의 표시값에 읽기 전용으로 합성한다.
3. 회원번호·가입일·필증 상태를 별도 요약 필드로 제공하고 민감한 값은 브라우저 응답 전에 마스킹한다.
4. 원격 실패·미설정·미일치 상태를 구분하고 홈페이지 저장값을 안전한 fallback으로 유지한다.
5. 고유 ID 매칭, 레거시 단일 매칭, 키 미설정, 5카드 렌더링을 테스트한다.
