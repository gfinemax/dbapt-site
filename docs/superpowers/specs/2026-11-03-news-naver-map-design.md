# 게시글 네이버 지도 설계

## 승인 근거

- 사용자는 자유게시판과 공지글에 네이버 지도를 표시할 수 있는지 확인한 뒤 구현을 요청했다.
- 승인된 흐름은 `네이버 길찾기 링크 붙여넣기 → 목적지 정보 인식 → 지도에서 위치 확인 → 저장 → 게시글에 지도와 길찾기 링크 표시`다.

## 목표

- 자유게시판과 공지사항의 등록·수정 화면에서 네이버 지도 길찾기 링크 한 개를 선택적으로 연결한다.
- 입력한 원본 링크, 네이버 장소 ID, 표시 장소명, 사용자가 지도에서 확인한 위도·경도를 구조화해 저장한다.
- 게시글 열람 화면에는 실제 네이버 동적 지도, 확인된 위치 마커, 장소명, 원본 네이버 지도 링크를 표시한다.

## 입력과 검증

- 허용 URL은 `https://map.naver.com/p/directions/...` 형식으로 제한한다.
- 길찾기 URL의 목적지 구간에서 표시 장소명, 장소 ID, 장소 유형을 추출한다.
- 장소 유형은 `PLACE_POI`만 허용한다.
- URL 안의 네이버 내부 축약 좌표는 공식 위도·경도로 해석하지 않는다.
- 사용자는 지도에서 마커 위치를 한 번 확인해야 저장할 수 있다.
- 서버는 URL을 다시 파싱하고 원본 URL, 파싱된 장소명·장소 ID, 확인 좌표를 함께 검증한다.

## 표시

- 게시글 본문 뒤에 네이버 지도 카드를 표시한다.
- 카드에는 장소명, 장소 ID, 반응형 지도, 마커, `네이버 지도에서 길찾기` 외부 링크를 제공한다.
- 지도 API 키 누락 또는 로딩 실패 시 장소 정보와 외부 링크를 유지하고 실패 상태를 사실대로 안내한다.
- 자유게시판의 기존 로그인/공개 공유 범위와 공지사항의 기존 공개 범위는 변경하지 않는다.

## 데이터

- `CoopNews`와 `FreePost`에 다음 nullable 필드를 추가한다.
  - `naverMapUrl`
  - `naverMapTitle`
  - `naverMapPlaceId`
  - `naverMapLat`
  - `naverMapLng`
- 기존 게시글은 모두 `null`로 유지되어 화면과 동작이 바뀌지 않는다.

## 제외 범위

- 네이버 길찾기 경로 자체를 사이트 안에 재현하지 않는다.
- 네이버 비공식 내부 API를 호출하거나 지도 페이지를 스크래핑하지 않는다.
- 임의의 `iframe` 또는 `script`를 게시글 HTML에 허용하지 않는다.
- 장소명만으로 자동 추정하거나 동일 이름의 지점을 자동 확정하지 않는다.
- 한 게시글에 여러 지도를 연결하지 않는다.

## 접근성 및 반응형

- 링크 입력, 지도 위치 선택, 제거 동작에 명시적 라벨과 키보드 포커스를 제공한다.
- 지도 클릭만으로 완료하도록 강제하지 않고 위도·경도 숫자 입력도 함께 제공한다.
- 모바일에서 가로 넘침 없이 지도와 동작 버튼을 세로로 배치한다.
- 새 장식 모션은 추가하지 않는다.
